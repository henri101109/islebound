# Online speedrun leaderboards + accounts (Supabase)

Islebound posts and reads scores over Supabase REST. The game works without this — speedrun mode still runs locally — but live boards / accounts stay empty until you configure a project and run the SQL below.

## Easiest path (do this)

1. Open Supabase → **SQL Editor**
2. Paste **everything** in [`SETUP_ALL.sql`](./SETUP_ALL.sql) → **Run**
3. Hard-refresh https://henri101109.github.io/islebound/

That one file covers scores, accounts, PRs, online presence, chat, replays (VID), bans, and all speedrun categories.

## Bans (name / account / client_id / IP)

`SETUP_ALL.sql` creates `public.player_bans` and seeds a **12-hour Matteus temp ban** (expires `2026-11-05 17:47:00+00`). The client also ships a matching hard-coded fallback so the ban applies on GitHub Pages even before you re-run SQL.

### Auto-ban on cheat submits

When `submitScore` sees a time below the category `floorMs`, or an invalid / short / mismatched replay (step anti-cheat fail), the client **immediately** applies a **24-hour** temp ban for that player:

- Persists to `localStorage` (`islebound-local-bans`) so this browser is blocked right away
- Best-effort `POST` into `player_bans` with `name_norm` + `user_id` + `client_id` + `ip` (when known) and reason `cheat: time below floor` or `cheat: invalid replay`
- `checkBanIdentity` then blocks submit / chat / presence / sign-in with **TEMP BANNED**

Re-run `SETUP_ALL.sql` (or at least the `Insert cheat auto bans` policy) so anon can insert those rows. Without the policy, local bans still stick on that device; cross-device bans need a SQL insert:

```sql
insert into public.player_bans (name_norm, user_id, client_id, ip, match_mode, expires_at, reason)
values (
  'NAME HERE',
  null,              -- or account uuid
  'client-id-here',  -- from islebound-client-id / logs
  null,              -- or 'x.x.x.x'
  'name_exact',
  now() + interval '24 hours',
  'cheat: time below floor'
);
```

After pasting `SETUP_ALL.sql`, optional IP ban once you know the address (Supabase **Logs → API** often shows request IPs):

```sql
insert into public.player_bans (ip, match_mode, expires_at, reason)
values ('x.x.x.x', 'ip', timestamptz '2026-11-05 17:47:00+00', 'temp ban cheat WRs');
```

Notes:
- Browser anon clients cannot read the real TCP IP inside RLS. Name + `user_id` bans are enforced in SQL policies; IP bans are enforced by the client (ipify) against `player_bans.ip`.
- True edge IP blocking needs a Supabase Edge Function that inspects `x-forwarded-for` / `cf-connecting-ip`.
- Banned players see: *You're temporarily banned from online features.* (submit / chat / sign-in / presence blocked).
- Speedrun floorMs (client anti-cheat): death/boat/coins_10/coins_25 = 5s, full_inv = 30s, fish cats = 28s, shark_cloak = 45s, serpent = 40s, coins_100 = 20s.

## Auth model (username + 4-digit PIN)

Accounts do **not** use Supabase Auth email/password/magic-link.

- Table `player_accounts`: `id` (uuid), `username` (3–12 A–Z / 0–9 / space), `pin_salt`, `pin_hash` (SHA-256 of `salt:pin` via Web Crypto in the client)
- After sign-up / sign-in the client stores a local session in `localStorage` (`islebound-auth-session`) with `{ token, user: { id, username } }`
- `profiles.id` matches `player_accounts.id` (not `auth.uid()`)
- Score rows set `user_id` / `is_account` from that local session; guests still submit with `user_id` null
- Because GitHub Pages is static, RLS is open to the `anon` key for these tables (client still hashes PINs and enforces username rules). Treat this as a casual game board, not high-security auth.

## 4b. Players online (presence heartbeat)

Optional. The mode-select screen shows `ONLINE N` from distinct recent heartbeats. Guests and signed-in players both count via a stable `client_id` in `localStorage`. If this table is missing, the game soft-fails (`ONLINE —`) and never breaks play.

```sql
create table if not exists public.players_online (
  client_id text primary key
    check (char_length(client_id) between 8 and 64),
  last_seen timestamptz not null default now(),
  username text
    check (username is null or char_length(username) between 3 and 12),
  -- signed-in account id for board online-dot matching (preferred over name fuzzy)
  user_id uuid
);

-- REQUIRED if the table already exists without user_id (live DBs often need this):
alter table public.players_online
  add column if not exists user_id uuid;

-- Optional activity fields for island-chat presence tooltips (SURVIVAL / SHARK% / LOBBY):
alter table public.players_online
  add column if not exists mode text
    check (mode is null or mode in ('menu', 'normal', 'speedrun'));
alter table public.players_online
  add column if not exists category text
    check (category is null or char_length(category) between 1 and 24);

create index if not exists players_online_last_seen_idx
  on public.players_online (last_seen desc);

alter table public.players_online enable row level security;

drop policy if exists "Public read players_online" on public.players_online;
create policy "Public read players_online"
  on public.players_online
  for select
  to anon, authenticated
  using (true);

drop policy if exists "Public insert players_online" on public.players_online;
create policy "Public insert players_online"
  on public.players_online
  for insert
  to anon, authenticated
  with check (char_length(client_id) between 8 and 64);

drop policy if exists "Public update players_online" on public.players_online;
create policy "Public update players_online"
  on public.players_online
  for update
  to anon, authenticated
  using (true)
  with check (char_length(client_id) between 8 and 64);
```

Client behavior: upsert every ~12s while the tab is open (also nudged when boards redraw / after sign-in); rows with `last_seen` within ~75s count as online. Heartbeat stores `username` (and `user_id` when signed in) so account nametag chips can show a green online dot. If `user_id` is missing from the table, the client soft-falls back to username-only matching and still shows `ONLINE N` (it does **not** disable presence). Optional `mode` / `category` power chat presence hover tooltips (`SURVIVAL`, `SHARK%`, `LOBBY`, …); if those columns are missing the client soft-drops them and keeps heartbeats working.

  to anon, authenticated
  using (true);

drop policy if exists "Public insert chat_messages" on public.chat_messages;
create policy "Public insert chat_messages"
  on public.chat_messages

## 5. Verify / how to test

1. Hard-refresh the game (`index.html` cache-busted scripts)
2. **ACCOUNT → SIGN UP** — username 3–12, PIN exactly 4 digits → should land on PROFILE
3. Sign out, **SIGN IN** with same username + PIN
4. Wrong PIN → `WRONG PIN`; taken username → `USERNAME TAKEN`
5. Open **SPEEDRUN** — finish a run while signed in → name locked gold → **SUBMIT**
6. Confirm row in Supabase **speedrun_scores** with `user_id` + `is_account`
7. Board should show a gold **NEW** tag on that time (also on category TOP 10 within ~7 days / matching `run_id`)
8. Account / fuzzy-matched rows show a gold **ACC** chip next to the name; same person can appear multiple times in TOP 10 with different times
9. Mode select shows **ONLINE N** after running the presence SQL (or **ONLINE —** if the table is missing)
10. While signed in, top-left HUD chip shows username + total playtime (opposite the top-right timer in speedrun)
11. **GUEST** path still works; guest scores omit `user_id`
12. Menus: click mode / category / ready / finish / account / stats (hover highlights)
13. **TAB** opens **ISLAND CHAT** (C/F still cast); Esc closes chat; SEND / Enter posts; unread pip when closed
14. Hover a name in the chat presence strip → parchment tooltip (`SURVIVAL` / `SHARK%` / `LOBBY`) after mode/category columns exist

## Notes

- Boards and the last used name are cached in `localStorage` for offline display
- The client rejects impossibly low times per category before insert
- One submit per speedrun attempt via client `run_id` (unique index) + `srSubmitted`
- Signed-in finish screen locks the display name; account names render bold/gold on boards
- **NEW** tag: matching just-submitted `run_id`, or `created_at` within the last 7 days
- **ACC** tag: account rows and fuzzy-matched guest names tagged to an account (does not collapse multiple times)
- TOP 10 is 10 score entries (same player may appear more than once), ordered by `time_ms` ascending
- **ONLINE**: `players_online` heartbeat (~12s); count rows with `last_seen` within ~75s
- **Nametags**: account / ACC rows use the gold/wood chip; unclaimed guests stay classic pixel text
- **Green pip**: accounts when that `user_id`/username is in `players_online`; guests only if presence fuzzy-matches their name
- **Island chat**: Tab toggles sidebar; C/F still cast; Esc closes chat; polls `chat_messages`; presence hover shows `mode`/`category` tooltip
- **R** resets the current speedrun category from ready or mid-run
- Normal mode still uses `survival-rpg-save` for world state and never writes speedrun scores
- Old email/magic-link sessions in `localStorage` are ignored / cleared on load
- Speedrun timer does **not** pause while chat is open
